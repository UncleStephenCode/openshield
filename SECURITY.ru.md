# Политика безопасности

О предполагаемых уязвимостях сообщайте владельцу репозитория конфиденциально,
до создания публичной задачи. Укажите затронутую ревизию, необходимые для атаки
условия, минимальный пример воспроизведения и наблюдаемые последствия. Не
прикладывайте действующие учётные данные или информацию из систем, которые вам
не принадлежат.

Поддерживаемая ветка — `main`. Исправление безопасности должно включать
регрессионный тест и, когда это уместно, обновление модели угроз.

Управление доступно только локальному root. Мониторинг только для чтения
разрешён root и членам системной группы `openshield`; членство открывает доступ
к сетевым правилам, конечным точкам, событиям, режиму и счётчикам, поэтому
является отдельной привилегией безопасности. Предпочтительный бэкенд — nftables,
при его недоступности используется проверенный резервный путь
iptables/ip6tables.

OpenShield намеренно считает недоверенными все входные данные протокола, в том
числе полученные от локального root-клиента. Во всём коде рабочего пространства запрещён
небезопасный Rust (`unsafe`); проект отклоняет выполнение команд оболочки, выбор
запускаемого файла из конфигурации, неограниченные IPC-фреймы и флаг NFQUEUE
`bypass`. Пути к исполняемым
файлам в исходящих правилах — это ограниченные типизированные селекторы
идентичности; демон никогда не запускает указанные файлы.

Начиная с OpenShield 0.1.31, демон сообщает режим политики, выбранный бэкенд
фаервола и динамически пересчитываемую классификацию активного тракта политики отдельными
полями `StatusV2`. Эта классификация не аттестует возможности ядра и не согласует резервный
тракт для неизменной политики. `KernelNative` означает применение политики через nftables/iptables,
а не application-aware data plane на eBPF. Этот релиз не добавляет `CAP_BPF`,
модуль ядра, изменение параметров загрузки или регистрацию MOK. При ошибке
подготовки обязательного NFQUEUE демон сохраняет исходный `BlockAll` и
завершается; он не подменяет политику ослабленным network-only-вариантом и не
включает bypass очереди.
Единственный автоматический резервный переход бэкенда при старте выполняется с nftables
на полный набор iptables/ip6tables, если nftables не прошёл проверку.
Если работающий демон перешёл в аварийный карантин только для чтения,
`StatusV2` использует отдельную причину `EmergencyBlockAll`, а TUI показывает её как
аварию; это состояние не смешивается с выбранным оператором `BlockAll`.

В OpenShield 0.1.32 обход владельцев в procfs распределяется не более чем между
32 уже готовыми пакетами NFQUEUE без ослабления атрибуции. `SOCK_DIAG` остаётся
отдельным для каждого пакета; захват ограничен двумя снимками владельцев;
повторное использование возможно лишь внутри одной пакетной операции;
обязательная идентичность процесса должна совпасть; на всю операцию действует
один абсолютный срок 250 мс, а для всех целей каждого снимка — общий предел
записей о владельцах. Типизированные
тайм-ауты остаются наблюдаемыми, а неоднозначность или исчерпание любого предела
приводит к запрету, а не обходу фильтрации. Проверка nftables теперь получает
таблицы, цепочки и счётчики одним фиксированным процессом, сохраняя прежние
инварианты, секундную периодичность и восстановление с закрытием при отказе.

Эксплуатационная граница, допущения закрытого при отказе поведения и
существенные риски сохранённых у демона полномочий исследования procfs описаны в
[модели угроз](docs/THREAT_MODEL.ru.md).

отдельно в [отчёте об аудите безопасности](docs/SECURITY_AUDIT.ru.md).
