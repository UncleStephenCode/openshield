# Упаковка демона

Установите `openshield-daemon` как `/usr/bin/openshield-daemon`, а unit-файл
systemd как
`/usr/lib/systemd/system/openshield-daemon.service`.

Сервис намеренно работает от root и сохраняет `CAP_NET_ADMIN`,
`CAP_SYS_PTRACE` и `CAP_DAC_READ_SEARCH`. Последние два полномочия позволяют
демону связывать inode поставленного в очередь сокета с защищёнными
идентификационными метаданными `/proc/<pid>` процессов разных локальных UID.
Фильтр системных вызовов всё равно запрещает `ptrace`, `process_vm_readv`,
`process_vm_writev`, `kcmp`, `pidfd_getfd` и `open_by_handle_at`, но эти
полномочия существенно увеличивают последствия компрометации демона и не должны
считаться полным разделением привилегий. В частности, фильтр не мешает
скомпрометированному процессу с `CAP_SYS_PTRACE` открыть `/proc/<pid>/mem` и
использовать обычные системные вызовы чтения и записи. `CAP_DAC_READ_SEARCH`
также позволяет обойти права чтения и поиска для файлов, видимых в пространстве
монтирования сервиса.

Сервис создаёт:

- `/run/openshield/control.sock` (`0600`) для изменений только от root;
- `/run/openshield/observe.sock` (`0666`) для очищенных данных состояния и
  событий только для чтения;
- `/run/openshield/daemon.lock` (обычный файл `0600`, принадлежащий root) для
  обеспечения единственного экземпляра демона и транзакции стартовой политики;
- `/var/lib/openshield/state.json` (`0600`) для атомарно сохраняемого состояния.

Не переносите сокеты в общий временный каталог и не ослабляйте реализованные
демоном проверки владельца runtime-каталога `/run/openshield`.

При первом запуске `BlockAll` устанавливается до открытия любого сокета.
Запускайте сервис только из локальной консоли или при наличии независимого
внеполосного доступа, затем используйте `sudo openshield-tui`, чтобы добавить
правила или перейти в режим Learning. При остановке сервиса политика остаётся
активной в ядре; явная процедура удаления фиксированной таблицы описана в
[корневом README](../../README.ru.md).

В `ExecStartPre` unit-файла вызывается не настраиваемая команда
`openshield-daemon --install-fail-closed`, доступная только root. Затем основной
процесс демона отправляет systemd уведомление `READY=1` только после применения
проверенного состояния, привязки фиксированного закрытого при отказе обработчика
NFQUEUE 1337 и обоих проверенных сокетов. У очереди нет флага nftables `bypass`;
если её нельзя привязать, запуск завершается с ошибкой, а `BlockAll` остаётся
активным. Не возвращайте unit-файл к `Type=simple`: иначе запуск сети перестанет
ожидать эту границу готовности.

Раздел `[Install]` содержит `RequiredBy=network-pre.target`. Команда
`systemctl enable openshield-daemon` создаёт эту зависимость; вместе с
`Before=network-pre.target` она не позволяет штатному потребителю цели пройти через неё, если
OpenShield не запустился успешно. Простое копирование unit-файла без его включения не создаёт
зависимость.

Это всё ещё не охватывает сетевой менеджер, unit-файл, initramfs или ранний тракт пакетов,
обходящие `network-pre.target`. Строгая защита всей загрузки требует проверенной интеграции дистрибутива
или фильтрации из initramfs.

`Restart=on-failure` может повторно запустить завершившийся с ошибкой основной
процесс, однако каждая попытка снова сначала устанавливает политику `BlockAll` до
запуска и не может сообщить о готовности, пока не активны сохранённая политика,
обработчик NFQUEUE и IPC-точки.

И `ExecStartPre`, и долгоживущий демон до обращения к nftables получают одну и
ту же неблокирующую блокировку единственного экземпляра. Поэтому ручной запуск
`--install-fail-closed` при работающем демоне завершается без замены активной
политики. Не удаляйте `daemon.lock`, пока одна из этих операций может
выполняться: освобождая `flock`, демон оставляет файл на месте, чтобы все
последующие процессы блокировали тот же inode. Упакованный unit-файл также
сохраняет runtime-каталог между остановками; при перезагрузке `/run` очищается
обычным образом.

Не запускайте второй менеджер фаервола, который сбрасывает весь набор правил
nftables. OpenShield пытается восстановить обнаруженную потерю таблицы, но
одновременная работа конкурирующих привилегированных сервисов не поддерживается.
