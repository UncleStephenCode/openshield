# CI и релизы OpenShield

Авторитетная документация релизного CI находится в
[`.github/README-CI.ru.md`](.github/README-CI.ru.md). Сам процесс задан в
`.github/workflows/release.yml`, а машиночитаемый контракт поддержки — в
`packaging/ci/release-matrix.json`.

Релизный граф закрыто отказывает при любом несоответствии:

```text
Validation
    -> Quality Gate
    -> 7 сборок двоичных файлов
    -> 18 сборок пакетов
    -> 34 установки в парах дистрибутив/платформа
    -> контейнерные тесты init-систем в закреплённых образах
    -> 59 сквозных тестов фаервола
    -> запечатанный релизный кандидат и свидетельства
    -> публикация
```

В 59 заданий входят 32 сценария nftables и 27 сценариев резервного
iptables. Tumbleweed i586 проходит оба сценария в режиме совместимости
`linux/386` на x86-исполнителе. Tumbleweed ppc64le и s390x явно отмечены как
smoke-тесты пакетов через QEMU и не выдаются за полные тесты фаервола
или сертификацию на нативном оборудовании.

Каждый публикуемый пакет связан со свидетельствами установки и фаервола по
имени и SHA-256. До первого запроса к API публикации задание с правами записи
независимо сверяет
тег, ревизию исходного кода, хеш матрицы, полный список файлов, размеры, digest
и `SHA256SUMS`.

Для создания релиза задайте `[workspace.package].version` в `Cargo.toml`, зафиксируйте
полное изменение и создайте совпадающий тег `vX.Y.Z`. Восстановление уже
опубликованного релиза разрешено только через явную опцию исправления
`workflow_dispatch`; существующие файлы с другими байтами никогда не перезаписываются.
