# CI и релизы OpenShield

Авторитетная документация релизного CI находится в
[`.github/README-CI.ru.md`](.github/README-CI.ru.md). Сам процесс задан в
`.github/workflows/release.yml`, а машиночитаемый контракт поддержки — в
`packaging/ci/release-matrix.json`.

Релизный граф закрыто отказывает при любом несоответствии:

```text
Validation
    -> Quality Gate
    -> 43 сборки двоичных файлов для пар семейство/архитектура
    -> 43 сборки пакетов для пар семейство/архитектура
    -> 37 установок для 19 вариантов пакетов
    -> контейнерные тесты init-систем в закреплённых образах
    -> 74 сквозных теста фаервола
    -> запечатанный релизный кандидат и свидетельства
    -> публикация
```

Матрица времени выполнения содержит 37 закреплённых пар
дистрибутив/платформа: 16 для `amd64`, 15 для `arm64` и 6 для
`386`. Каждая строка проходит сценарии с приоритетом nftables и только
с резервным iptables. `amd64` и `arm64` выполняются на нативных
исполнителях GitHub; `linux/386` — через прямой 32-разрядный режим
совместимости ядра x86-64.

Все 43 цели двоичных файлов и 43 цели пакетов по-прежнему
собираются. Оставшиеся 24 варианта пакетов для ARMv5/6/7,
PowerPC64LE, RISC-V 64 и IBM Z имеют статус «только сборка» и соответствуют 49 из
86 объявленных пар дистрибутив/платформа. Их тракт Cross/QEMU проверяет ELF и
выполняет непривилегированный
smoke-тест `--version`, но не даёт свидетельств установки пакета или
работы фаервола. Публикация такого артефакта не означает заявления о
поддержке во время работы или на нативном оборудовании.

Каждый пакет из проверяемого набора связан со свидетельствами
установки и фаервола по имени и SHA-256; пакеты со статусом «только
сборка» имеют только свидетельства сборки и целостности артефакта. До
первого запроса к API публикации задание с правами записи независимо
сверяет тег, ревизию исходного кода, хеш матрицы, полный список файлов,
размеры, digest и `SHA256SUMS`.

ZIP-транспорт артефактов GitHub нормализует режим обычных файлов до `0644`.
Поэтому Release Evidence явно требует этот режим от загруженных транспортных
копий ELF и использует их только для сверки байтов. Источником исполняемого
режима остаётся публикуемый `tar.xz`: он должен содержать ровно демон и TUI как
обычные файлы с режимом `0755`, а их размеры и SHA-256 должны совпадать с
транспортными копиями. При сборке пакета режим `0755` задаётся явно.

Для создания релиза задайте `[workspace.package].version` в `Cargo.toml`,
зафиксируйте полное изменение и создайте на этой ревизии совпадающий тег
`vX.Y.Z`. Числовой тег `X.Y.Z` без обязательного префикса `v` доходит только
до Validation, где завершается с явным сообщением об ошибке; компиляция и
публикация для него недоступны. Восстановление уже опубликованного релиза
разрешено только через явную опцию исправления `workflow_dispatch`;
существующие файлы с другими байтами никогда не перезаписываются.
